## 为什么分别改后端和 prompt

|缺陷与证据|修复位置|已落实的改动|边界|
|学术缓存根值 null 导致渠道失败|后端|容错恢复、坏文件留档、原子写入、并发锁|不解决上游限流或权限|
|摘要无标记截断，误认已读全文|后端工具契约|offset/max_chars 续读、实际范围、内容 hash、证据层级|只覆盖已取得的摘要；上游自身完整性未知|
|本地摘要只有 519 字且句中截断，却显示 complete_abstract|后端（首轮对照中新发现）|改为 available_abstract；完整窗口与原始摘要完整性分开|不伪造缺失部分，也不声称已获得论文全文|
|多次阅读、不同译本混成“读完”|后端 + prompt|按书籍、章节、全文 hash 合并实际返回区间；显示缺口|整章没读完不等于用户要求的目标段落没读完|
|原典链接拼错或没有链接|后端 + prompt|章节和引文工具返回真实 `/reader/{id}?ch={idx}`，prompt 使用返回地址|仅承诺章节级，字符坐标不冒充阅读器锚点|
|未命中变成伪托，成功变成故障诊断|prompt + 状态字段|未命中明确标归属未定；prompt 要求结论守住检索范围|模型仍可能违反；没有用正则改答案|
|擅自诊断心理、偷换范围、定义充当论证|prompt|第二轮改为接住问题、保留假设、价值标准与桥接理由分开|复测仍失败，不宣布已修好|
|制度定义遗漏，原典被套用到新情境|prompt|核查适用定义/例外，类比说明限度|没有为单题写固定结论|
|无法区分模型、prompt、代码变更的作用|版本与评测层|manifest、prompt/hash、代码 hash、模型与依赖、工具集合、预算状态随流记录|网络材料与抽样仍会变化；不是完美因果实验|

主 agent 保持 bare 管线，没有加入工具次数、轮数、token 预算、去重门禁或“必须查 N 次”的规则。评测 runner 的 600 秒超时是实验控制，不是产品运行预算。辅助模型计费未纳入主模型 usage，不谎报总成本。

## 尚未解决与晋升条件

1. prompt 仍有心理归因和概念越界，优先重新检验而非加禁止词列表。余额恢复后补完同题、多次抽样及未见问题；必要时作模型能力对照，再决定是否晋升。已见题只能作开发回归。
2. 秘塔没有可用接入；OpenAlex 429、出版社 403、论文全文可达性仍不稳定。缓存恢复/摘要分页不能冒充渠道全部修复。
3. SDK 在退出时仍出现 httpcore2 异步清理噪音；本次完成轨迹没有流错误，但不能把日志异常说成已修。
4. 故障组 K01–K05 fixture 仍未建设；HTTP/SSE/移动端整链路不是此次进程内题测的覆盖范围。
5. 50 轮只有未验证自动初评，稳定质量验收仍需独立复核。数据库未扩充、评分冻结文件和原始 run1/run2 轨迹未修改。

应先把这些证据做扎实，再给稳定 2.0 打标签上线。当前交付是可追溯、可比较、可回退的修正版候选，不是“质量已提升”的宣传结论。
