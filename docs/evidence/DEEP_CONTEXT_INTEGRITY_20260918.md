# 通用推理材料完整性修复

本轮从实际模型输入发现两处信息损失。它们发生在正常返回之后：工具已经产出反例和限制，主模型却可能只收到结论开头。不是公开工具卡片的摘要长度问题。

产品修复提交：`f4ad72c03`。本轮仍保留 `deepseek-flash / high / 16384` 默认配置；线上服务未切换。

## 已验证的修复

`tools_node` 原先将所有结果 JSON 按前 4000 字符切断；已经消费过的普通工具结果在下一轮又压成前 240 字符。离线捕获真实 LangChain 请求序列化表明，`additional_kwargs._result_full` 不会补发给模型。5205 字符的论证产物和 5160 字符的评审产物被截成非法 JSON；约 1000 字符的完整短产物也会在后续轮丢失反例、最强回应等字段。前后数字见[完整性审计](DEEP_TOOL_CONTEXT_DELIVERY_AUDIT_20260918.json)。

现在通用工具按已有能力表识别推理和生成产物：24,000 字符内完整传递合法 JSON，后续轮及各类复用保持同一内容。超限时返回明确的整体遗漏通知，不选择性保留结论；公开状态显示错误与“结果未完整传递”，同时记录实际执行状态。完整原产物仍留作审计。尼采继续使用原来的传递和压缩路径。

论证检查的另一处前缀截断也已移除：普通问题、附件及指定回答组成的请求在 40,000 字符内完整保留；超过时保留头尾并明确提示中部遗漏。待分析论证从原先静默取前 6000 字符，改为接收完整的 20,000 字符内输入；超限明确返回错误，不假装已经审查另一份残缺论证。长附件后面的实际追问和论证末尾结论均有回归覆盖。

这些修复保证材料送达，不保证模型会正确利用材料。主提示词和模型配置未因本轮完整性修复变化。
