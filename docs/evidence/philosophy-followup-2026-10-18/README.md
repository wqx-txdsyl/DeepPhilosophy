# 隐含续问职责检查（2026-10-18）

## 已复现的遗漏

`deployed-reproduction.json` 是公开线上 v0.1.6 的匿名请求：使用依据截图重建的合成旧工程回答，再发送用户原话“在解释一下”。回执证实 v0.1.6 仍继续推导轮速与 √2 投影，确实遗漏了隐含续问，而非仅凭截图猜测缓存问题。未取得用户原文件或访问其账户历史。

截图的 v0.1.5 位于上一条回复的尾部；前端版本来自各条回复自己的回执，不能据它推断后续请求实际版本。旧回复的记录和版本不改写；提示文字明确其为“本条回复生成时”的版本。

## v0.1.7 的实现

存在历史回答、指定旧答或本轮附件时，先解析本轮实际请求与它指向的材料，用配置的 API 模型作一次关闭思考、无工具、JSON 枚举输出的范围判定。判断实际要继续的工作，不按“再解释”或“公式”等关键词封禁。辅助检查只读近期上下文、指定回答和标明边界的材料片段；主回答仍接收原始历史和完整已提供材料。

- 范围内：进入原主模型与工具流程。
- 超出哲学职责：直接说明边界，不加载主模型与工具，不生成工程推导；不把辅助判定冒充哲学家思考。
- 指代不明：确认要讨论的哲学问题。
- 网络、格式或不完整回执：报可重试错误，不默认放行。取消会中止检查。
- 首次空要求上传仍沿用 v0.1.6 的直接确认分支，不调用模型。

辅助调用有独立 `scope_check` 回执、实际用量与 policy_sha256，不计入 main_agent_only 用量。未引入主模型工具总预算，没有修改哲学家人格或重写既有聊天。历史 v0.1.5/v0.1.6 配置不启用新检查。辅助判定会增加延迟，也可能有误判；不是对任意诱导都不可突破的保证。

## 真实定向验收

最终 `cases.json` 与 `results.json` 保留 17 个实际请求的输入、预期、辅助判定、主模型是否启动及公开答复。辅助判定使用真实配置的模型；范围内的主回答也调用真实模型。没有保存隐藏推理。主工具声明保持可用，测试夹具不执行真实外部工具与额外延伸问题请求；请求的工具名均留档。

覆盖“在解释一下”“再解释一下”“简单一点”“继续”“代入数字”“解释根号二”“还有吗”、明确转向科学哲学、正常哲学续问、指定较早回答、历史伪造指令、结束讨论、首次相对附件提问、无历史但有指定回答。

最终 17 个判定均符合记录的预期。工程续问未进入主模型；科学哲学续问、明确切换哲学目标和哲学附件解释正常进入；致谢结束没有被误当工程任务。纯技术附件的相对提问也在主模型前停止。不得把本组结果当作完整哲学质量跑分。

前期记录保存在 `initial-14/` 与 `classifier-refinement/`。追加附件与停止话题用例曾暴露误判：把首次哲学附件当指代不明、把致谢当延续旧工程。判定提示词改为先识别当前意图，再解释所指对象，最终完整组全部重跑；没有挑选旧答案拼成最终集。

模型流结束后的 SDK 异步清理告警仍在测试进程中出现；已收到完整 done 的用例与告警分别记录，本轮没有扩大修复 SDK。

## 上线复核

公开 SSE 与公开浏览器均以同类旧工程上下文发送“在解释一下”：新回执为 v0.1.7，scope_check=out_of_scope，主模型未调用、未执行工具。浏览器用全新访客存储预置合成旧答，没有拦截接口或访问真实账号；旧答仍标 v0.1.5，新答标 v0.1.7。见 deployed-acceptance.json、browser-checks.json 与 deployed-browser.png。

另作3个真实范围检查（并非重跑主模型）：边界提醒后再说“再解释一下”、明确要求继续数字推导，均未放行；明确询问产品为何不做该类任务则允许。见 repeated-scope-check.json。集成后85项相关后端检查、前端回归与构建通过；新检查默认在bare主路径执行，历史controlled路径未作本轮行为验收。
