# v1.2 校准与冻结报告

日期：2026-09-27。结论：**操作规范已固定；自动评分校准未通过。** 不把“写好了规则”说成“已经证明评分可靠”，不恢复 v1.1 的跨文体排名。

## 样本和复核来源

6 道同任务题，20 份构造答案：每题一份参考答复、一份简洁答复、一份关键错误答复；另加重复引文与不同立场各一份。覆盖康德概念细读、休谟论证重构、康德/休谟比较、亚里士多德友爱论迁移、教师动机的规范判断、《论语》引文负结果核验。

原典只供核查，不参与排名。材料来自现有书库 SQLite 的只读查询；保存连续摘录、章节、字符位置和摘录 SHA-256。引文核验包使用真实 verify_quote 回执（本库该版 22 个文本单元，未命中），不是模型声称做过检索。材料中原有的 OCR 痕迹原样保存，没有借校准修改书库。

答案由本任务的 Codex 构造；评分器为配置中的 DeepSeek API，请求和返回模型名均为 deepseek-flash。评分器拿到任务、材料和匿名答案，不拿构造标签。第一轮 9 次请求，第二轮 25 次请求，共 34 次；保存请求和原始响应。不是多位人类专家复核，也不是线上 PhiAgent 的真实回答表现。供应商 usage 合计 91,631 tokens，仅用于记录请求量，不代表 Codex Pro 用量。

本轮没有重新给用户之前四家 AI 的安慰题排榜，也没有完整覆盖外网博客、学术论文或未见题；这些不能被本轮 6 题替代。

## 第一轮失败及修订

第一轮批量评分中出现：研究任务只评 R、不评 C；输出字段不合协议；把重复的准确转述误当作伪造；长短答差异过大。9 份响应中只有 3 份通过当时的严格结构检查。

同时发现样本自身问题：T3 短答没充分展开题目要求的两段推理；T5 评价准则的说明不足。第二轮补齐相应内容，没有预先假定所有短答都与长答等效。

第二轮在请求前重新登记文件指纹：明确 R 题评 C+R，转述不同于逐字引文，材料包 ID 足以定位，低分必须对应必要工作；改为一份答案一请求。未改变权重或通过阈值。第一轮设计保存在 round1_design，原响应保存在 review_round1。

### 分歧需要怎样处理

T1 短答已说清经验范围限制，评审仍要求额外展开题外竞争解释，存在过度要求的迹象。T5 参考答复的“不能据此判甲更好”被认为不是有限判断，这一评语也需复核。另一方面，T4 短答只说“不同根据”，没有明确展开两种友爱，确有样本压缩过度的可能。不能把所有不符预期的分数一概算作评分器错误。

构造者希望参考答复通过，只是校准假设，不是正确性证明。下一轮要先独立核对样本和任务负荷，再检查评分器，不能修改分数或不断加长短答直到过线。

## 确定性验证

离线脚本 validate.py 检查原始响应，不调用模型、不改变原分。12 项单元测试通过：C 不归一化、C/R 分开、U 不当 0、0 不当空值、缺项/多项拒绝、非法等级拒绝、核心低分不可补偿、研究低分不可补偿、K 二元量尺、严重错误覆盖总分、错误必须有证据、按精确值而非展示分判定。

第二轮登记的 5 份设计文件指纹均匹配；8 份原典摘录的文本指纹、索引字符区间和来源路径均与本地只读索引一致（这不等于核实出版版本权威性）。冻结规则与第二轮规则的计分内容一致，未事后改权重。验证结果为 VALIDATION_RESULTS.json，来源核对为 SOURCE_AUDIT.json。可在仓库根执行：

```sh
python3 docs/evidence/rubric_v1_2/validate.py
python3 docs/evidence/rubric_v1_2/verify_freeze.py
```

脚本成功运行代表计算与审计完成，不代表自动评分器通过；必须读取 automated_evaluator_accepted（当前 false）以及逐项状态。

## 冻结决定与限制

固定[规范正文](PHIAGENT_ACADEMIC_RUBRIC_V1_2.md)和候选数字规则，作为可追溯的开发评测协议；**不批准自动打分上线，不把候选通过线当作已验证质量门槛**。这是比原草案更窄的冻结范围，不是满足了原草案“全校准通过再冻结”的承诺。失败本身就是此次验证结果，不能以冻结名称掩盖。

冻结清单只保证记录未被静默改写，不保证哲学解释为真。没有人类专家一致性、统计置信度或跨题泛化证明。权重和门槛属于开发约定，尚无充分经验支持；独立专家复核和新题通过后，另行发布验收决定。

当前允许：定位疑似错误、按固定标准记录人工复核、比较同题证据与论证缺口。当前不允许：靠一轮自动分宣布 SP 更强、把一次答案外推为模型总体能力、跨体裁评康德与 ChatGPT 谁更强。
