# PhiAgent：Chat 与 Project

设计日期：2026-10-18。**当前状态：应用户要求，Project 已下线。** 前端入口移除，原项目链接返回 Chat，所有项目 API 返回 410，原数据保留；下文实现与验收仅记录撤下前的版本，不代表现有线上功能。

## 两个分区，各自解决什么

| 分区 | 用户想做的事 | 打开时首先看到什么 | 主要留下什么 |
| --- | --- | --- | --- |
| Chat 对话 | 问一个问题、与哲学家交谈、试探一个观点 | 问题与回复 | 可回访的对话，及明确保存的个人偏好 |
| Project 项目 | 让一个问题经过材料、异议和行动，形成可继续修订的成果 | 上次工作的对象、当前判断、未完成事项 | 文稿与版本、资料与定位、分歧、任务、实际行动及反馈 |

顶层是 **Chat / Project** 切换；身份、登录、主题、书库及现有 40 位哲学家共用。两个分区分别保存导航位置，不把项目当作 Chat 的聊天文件夹，也不要求自由提问先建项目。项目讨论可以很长，但讨论记录不是项目成果的唯一载体。

Chat 的 `/agent`、`/agent/c/:id` 保留。新建 `/projects` 项目列表、`/projects/:id` 项目恢复页、`/projects/:id/o/:objectId` 工作对象、`/projects/:id/runs/:runId` 任务定位。此处是新路由设计，不修改现有路由或组件名。PWA 同一个安装包将来容纳两区，不需要再装一个应用。

## 核心工作空间

桌面默认三列：左侧项目对象，中间正在工作的材料、文稿或行动计划，右侧围绕当前对象的讨论与任务。中间占主要宽度；右侧可展开，用户始终能看见本次修改落在哪里。窄屏改为“对象 / 讨论”切换，不把三列缩成窄条。

项目恢复时不是先展示庞大的仪表盘，而是回答：我们在问什么，上次写到哪里，什么异议还没有回应，接下来准备做什么。项目名可以只是一个问题；创建只填标题，成果形式、时间、资料与成员按需补充。

左侧初版保留四组对象：

- **项目简报**：问题、范围、当前工作假设、预期成果和下一步。允许不确定，不做“真理完成度”。
- **资料**：原典定位、上传文件、笔记、实际访谈和其他研究材料。资料是否已读、读了哪一段、是原文还是解读，明确区分。
- **工作对象**：文稿、争点、论证记录、方案与行动记录。对象有稳定身份、版本和关联资料。
- **讨论与工作记录**：围绕某个对象的交流、任务及修改经过。进入另一对象不会把原任务输出写错地方。

上方的“研究 / 研讨 / 实践”是同一项目的工作方式，不是三个独立产品。切换改变当前可见的工作对象与工具，不复制资料和结论。

## 用一个真实问题串起三种工作

示例项目为“AI 参与写作时，作者应承担什么责任”。以下内容仅用于原型，不是已经完成的研究或真实成员记录。

**研究**：加入责任与作者性相关材料，写一篇初稿。选中一个段落，请深哲补材料或让康德提出异议。模型意见以修改建议出现，可查看原段、建议及理由，采纳后生成新版本。引用能回到实际材料；人物模拟发言不能直接成为原典引文。

**研讨**：把“披露 AI 使用是否足够”变成一个争点。真人成员和哲学家模拟角色分别发言，回应的是明确主张。主持者可留下“未解决分歧”，不强制形成共识，不拿模型多数票当论证成立。真实辩论必须有真人参与或可追溯的真实讨论记录，不能用几个人格模型冒充真人辩论。

**实践**：从讨论形成一个小规模写作工作坊方案，说明参与者、要试什么、怎样记录反馈、什么观察会使我们修改判断。初始状态是“尚未获得真实反馈”。真人执行后录入记录，方案依据这些记录形成下一版本。模拟推演与真实观察分开，不生成不存在的受访者、完成情况或效果数据。

三种工作共享材料与成果：一项异议可以关联文稿段落，也可成为一次实际试验的待检验问题；反馈又能回到论证。项目允许最终保留分歧。

## Agent 在项目中实际做什么

Project 不能只是“带背景的 Chat”。用户应能请求：核对一段引文、比较两份材料、给一个论证找反例、修订一段文稿、把争论整理为尚待解决的问题、依据真实反馈修改方案。

深哲负责研究主持、材料处理和通用工作；哲学家保留自己的思想、口吻和历史知识边界，按明确职责参与。职责不能把康德、庄子或毛泽东都改成同一位中立助理，也不能把后人的评价塞回人物的自传。默认一位执行者，按需请第二位提出有目标的异议；不默认召集 40 人开会。

每项任务绑定项目、目标对象和起始版本，展示本次取用的材料与当前工作。运行可停止，部分结果可保留；重试不重复写入。编辑普通草稿的授权可以持续生效，不每改一句就弹许可框；用户已定稿的文本和已采纳判断要保留旧版，修订以可检查的变化交接。发布、发送给外部人员、真实行动和定时工作另有明确用户动作。

## 什么进入持续上下文

| 层次 | 默认允许进入的内容 | 不自动带入 |
| --- | --- | --- |
| 账户 | 登录身份与显示主题 | Chat 的偏好、记忆和历史，其他项目的私人资料和结论 |
| 项目 | 项目简报、当前对象、相关来源、未解决问题和续接点 | 全部聊天逐字拼接，整库文件无差别注入 |
| 任务 | 用户本次要求、目标版本、必要材料及相关讨论 | 恰好显示在屏幕上的另一个项目或对象 |

模型说过、用户采纳、原典可证与现实已观察是四种不同状态，不能靠一次摘要混成“项目记忆”。删除或撤回的资料不得通过旧摘要、缓存、先前问题或引用副本重新进入模型。跨项目引用需要明确来源与权限，不做静默全局知识池。

## 保存、版本与材料

使用现有账号作为所有权边界。项目元数据与版本通过受认证的 API 保存；原始私有文件放受权限保护的对象存储，或当前部署的私有持久目录，由存储适配层隔离位置差异。首版按当前网页版服务实现，并提供导出；不承诺 PWA 能自动访问任意本地目录。桌面本地工作目录与云端同步是后续可选能力。

现有上传主要完成转文本，不等于持久保留原始文件。项目必须同时保留原文件对象和抽取文本版本的关系。公共书库按书籍 ID、版本与定位引用，禁止把私人项目写入 `app/public/`，也不改动 `backend/data/book_chapters/`。

文稿每次修改都记录来源版本。并发修改返回冲突而非覆盖；素材改变时关联判断标“待复核”，不偷偷改写作者观点。切换项目后，任务仍写回原项目和对象。成员权限初版为所有者、编辑、评论、阅读，邀请需接受后生效，未分享资料不随项目邀请泄漏。

长期设计对象包括 Project、Membership、Source、Artifact、Revision、Relation、Run、Action、Feedback。Chat Conversation 不增加 project_id，不提供自动归入项目、搬运聊天或共用记忆；Project 使用独立项目与任务数据表和 API。Run 内记录项目、对象、来源版本、状态、续接点与结果；Relation 关联段落、材料、主张、异议或行动，初版用列表完成，不强推复杂自由图谱。

## 首版按三条可验收流程落地

1. **研究闭环**：建项目 → 加原典定位与一份资料 → 对照阅读 → 写初稿 → 产生并采纳一处有依据的修订 → 导出带出处的成果 → 重开后恢复。
2. **研讨闭环**：邀请一位真人并接受 → 围绕同一争点发表和回应 → 请一位模拟哲学家提出异议 → 保存仍未解决的分歧与后续问题。实时音视频与实时多人编辑后置，异步真人讨论不能缺席。
3. **实践闭环**：保存一个可执行方案 → 真人执行 → 录入一条真实反馈和凭据 → 区分观察与解释 → 形成下一版方案。没有反馈时明确空态，不能拿模拟结果通过验收。

先实现项目与对象持久化、资料定位和版本，再接对象上的讨论与任务，随后把真人研讨与实践反馈跑通。首版不同时铺开自由图谱、插件市场、全员自治、复杂工作流或数字化“真理评分”。

必须测试跨账号与跨项目隔离、停止和恢复、目标对象切换、重复提交、版本冲突、资料删除传播、未读来源、退出重开及导出。验收衡量能否推进一个实际成果，而不是对话次数或角色数量。

## 当前交付边界（2026-10-18 修订）

用户明确要求 Chat 和 Project 完全独立，本节取代前版的“Chat 带入项目”交互。共享账号、主题和公共书库不意味着共享历史、记忆、导航或模型上下文。

已实现：`/projects` 私人项目列表、`/projects/new` 新建、`/projects/:id/brief` 简报、`/sources` 资料、`/objects/:id` 工作对象、`/runs` 任务记录。列表→新建→项目→返回列表、直接链接、浏览器前进后退均有独立目标；未保存编辑离开项目时提醒，同项目内切换保留编辑。不存在的对象明确报错，不跳到无关 Chat。

数据写入认证数据库的 `phi_projects` / `phi_project_runs`，仅依据服务端登录身份授权；不写 Chat 会话或记忆，也不读取它们。当前每项任务读取本项目简报、资料摘录与现有工作对象，直接调用研究模型，不经过 Chat 编排或记忆工具。资料链接仅定位，尚无自动网页读取；界面和提示词都明确此边界。

任务结果先作为建议显示，采纳才写入目标对象；对象保存旧版本，revision 防止过期写入。停止、删除、资料变动与服务重启都有对应状态，过时任务不覆盖新修改；资料变动撤回旧建议。可以编辑资料、手动恢复历史稿、导出文稿、导出/导入完整项目 JSON。导入生成新的独立项目。PWA 不缓存私人项目 API。

研究、争点、行动各有独立工作对象。研讨方案与反方重建已可保存，但真人邀请、实时协作、自动资料搜集、原始附件托管和真实行动执行仍未提供。不能将这次文本研究冒充真人辩论或田野验证。

真实验收问题是“儒家思想对于今天是否还有其存在的价值？如何正视尊孔和批孔的斗争问题？”隔离测试身份完成七份资料、初稿、最强反驳、尚未执行的读书研讨方案和审读后修订；浏览器新建、保存、重开、采纳、引用导航、两项目/两账号隔离、导出导入及手机布局通过。项目包可导入实际账号，不冒称已在用户本人账号创建。见 [验收材料](../evidence/project-workspace-2026-10-18/README.md)。
