# 分章标准规范（DeepPhilosophy 章节体系）

> 适用范围：`book_chapters/{bid}/*.json` 章节文件、`meta.json`、四层同步。
> 依据：前端 `ReaderPage.jsx` / `ChapterReader.jsx` 实际解析逻辑 + 库内实例（单行道/机械复制/技术与时间/与神合一）。
> 最后修订：2026-08-10（由 291/294 list 旧格式事故 + toc 标题混乱事故总结而来）

---

## 1. 章节文件格式（硬标准）

每个章节一个文件 `{index}.json`，**顶层必须是 dict**，禁止旧引擎顶层 list：

```json
{
  "index": 3,
  "title": "一、波希米亚人",
  "content": [
    {"type": "text", "value": "正文……"},
    {"type": "text", "value": "……"}
  ]
}
```

- `index`：与文件名数字一致（0 起连续）
- `title`：清洗后的章节标题（见 §4）
- `content`：块数组；块类型目前只使用 `{"type":"text","value":str}`；图片以 `[IMG]` 内嵌于 value 中被前端拆段
- **为什么必须是 dict**：前端 `loadChapter` 把文件 JSON 展开进章节数组，list 顶层数组展开后没有 `content` 字段 →「点开正文无内容」（291/294 事故根因）
- `meta.json`（同目录，非章节文件）：
  - `chapterCount`：章数，必须 = 章节文件数（0..N-1）
  - `chapterTitles`：string 数组，`chapterTitles[i]` 必须 = `{i}.json` 的 title
  - `toc`：分级条目数组（见 §2）
  - `title/author/region`：书元数据

## 2. toc 分级标准（meta.toc）

toc 是**对象数组**；旧引擎的字符串平铺数组（`["总序","一波希米亚人"]`）禁止用于新书，前端字符串条目自动转 chapter 仅为兼容。

### 2.1 条目类型

| type | 含义 | 可点 | 渲染 | 字段 |
|---|---|---|---|---|
| `part` | 分部/编/卷，纯分组标题 | ✗ | `— 标题 —`，字重 700 | title, index, level |
| `chapter` | 标准章，有独立内容文件 | ✓ 切章 | 13px，缩进 14 | title, index, level |
| `section` | 章内节，**形态多样（见 §2.3）** | ✓ | 11px dim，缩进 42 | title, index, [sec] |

- `level`：chapter/section 一律 1/2；part 的 level 语义：
  - `level=0` 卷级（技术与时间「第一卷 爱比米修斯的过失」）
  - `level=1` 书内部分组（技术与时间「第一部分 人的发明」、与神合一内部的部分级）
- part 的 `index`：取其后第一个可点条目（chapter/section）的 index（库内惯例，技术与时间 part index=2 / 4）

### 2.2 判定原则（这条章级 vs 节级）

- **有独立内容文件的条目一律 chapter**（能切章阅读）
- 章内的小节标题（书内节名，如「1.对跖人」「一、话语煸动」）用 section
- 书的**分部标题**（编/部/卷，无内容文件）用 part

### 2.3 section 的多种情况（重点，禁止一刀切）

section 不只有一种实现，按书型选用：

**a. 锚点型（章内滚动）** —— 技术与时间式
```json
{"type": "section", "title": "1.一般历史与技术史", "index": 5, "sec": 1, "level": 2}
```
- `index` = 所属章的章节文件号，`sec` = 该节在章内正文的**块序号**
- 点击：切到 index 章 + 滚动到第 sec 块
- 适用：章是大文件（几十上百块），节名与正文块首对齐

**b. 独立小节文件型** —— 机械复制式
- 小节各自独立成文件（如「1.前言」「2.机械复制」……每节一个 json）
- toc 里用 `chapter` 平铺（机械复制 49 节全 chapter）或 `section`（带 index 无 sec）均可，前端都支持切章
- **选型**：节名带序号、每节一个文件 → 推荐 chapter 平铺（简单直白）；若要视觉强调节级 → section + index（无 sec）

**c. 标题锚点型（sec 缺失/不可靠）**
- 正文中由重建脚本插入 `<span id="sec-{tocIdx}">`（toc 全局下标），ChapterReader 优先按标题文本匹配正文、回退 `sec-{tocIdx}`
- 适用：OCR 重建书，sec 块号不可靠、标题嵌在块内
- section 条目 `sec` 可缺省，前端按标题锚点定位

### 2.4 前后置内容

- 总序/出版说明/译者序/作者序/献词/后记/索引等**独立成文件的条目**都是 chapter（index 0..N-1 顺排），不必进 part
- 只有真正的书内结构（编/部/卷）才建 part

## 3. 标题清洗规范（toc 标题可修，正文 OCR 残字不修）

1. **剥页码**：标题内不得残留「..31」「(105)」「·.·」（OCR 目录页页码粘连）
2. **编号规范化**：目录编号粘连要拆开补全
   - 「一波希米亚人」→「一、波希米亚人」
   - 「二游荡者」→「二、游荡者」
   - 缺编号补全：「傅立叶与拱门街」（第三部第一节）→「一、傅立叶与拱门街」
3. 章级标题用书名原文格式（《论波德莱尔的几个母题》等），不加自造编号
4. 保留繁体字、保留原书引号（"知识论"）
5. chapterTitles 与 toc 条目的 title 必须逐条一致；toc 里 part 的 title 为分部原名（第一编 我们的镜式本质）

## 4. 与文件结构的对应（防呆清单）

| 书型 | 例 | toc 结构 |
|---|---|---|
| 长文分节，每节独立文件 | 机械复制时代的艺术作品 | chapter×49 平铺（或 section+index） |
| 大部头，编/部/卷内章 | 哲学和自然之镜 | part（编）+ chapter（章） |
| 章内含小节（大章文件） | 技术与时间 | part（卷/部）+ chapter（章）+ section（章内锚点 sec=块号） |
| 简短条目书 | 单行道 | chapter×N 平铺（无 part） |

## 5. 四层同步（任何修改后必做）

- 章节文件 `book_chapters/{bid}/` ×3：P1 `DeepPhilosophy/backend/data/`、DP `PhiAgent/backend/data/`、APP `DeepPhilosophy/app/public/backend/data/`
- `book_detail/{bid}.json` ×3：P1/DP（backend/data）+ APP（app/public）—— toc/chapterTitles/chapterCount 必须一致
- `books.json` ×2：APP 根 + `app/src/assets/`
- `books_catalog.json` ×2：P1/DP
- ckpt（仅 DP `dp_pdf_import_ckpt.json`，P1 保持引擎原始）
- 写回 ckpt 后必须读回验证（曾出现静默失败）

## 6. 验收清单（每本书交付前）

1. 章节文件顶层全部 dict，`{index,title,content}` 完整，index 连续
2. `meta.chapterCount` = 文件数；`chapterTitles` 与文件 title 逐条一致
3. toc 无字符串条目、无编号粘连、无页码残留、part/chapter/section 分级符合 §2.4 防呆表
4. 四层同步后三处 detail 的 toc/chapterTitles/chapterCount diff 为空（extract 字段除外）
5. 前端验证：`http://localhost:5173/reader/{bid}` 正文可读、目录分级显示、点击各条目可切章

## 7. 事故溯源（2026-08-10，为何出错）

- **291/294 无正文**：重建脚本用 list 旧格式写章节文件（与同批 dict 格式脚本模板不统一），前端读 `content` 字段失败
- **291/294 标题混乱**：toc 未按本规范清洗分级——编号粘连（一波希米亚人）、缺编号（傅立叶与拱门街）、编+章平铺字符串（第一编·第一章 心的发明）
- **如何避免**：① 章节文件只认 dict 模板；② 新书重建后跑 §6 验收清单；③ 修改任何章节文件后四层同步 + 前端实测，不能只查文件不查展示
