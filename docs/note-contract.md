# 章末注释数据约定 note-contract v1（2026-10-24）

> 适用范围：`backend/data/book_chapters/{bid}/{i}.json` 章节文件与前端阅读器（ChapterReader）。
> 目标：正文脚注引用 → 章末注释 → 原引用位置的双向跳转；全库统一格式，禁止每本书另发明格式。
> 原则：向后兼容（无 `notes` 字段的章节渲染行为与旧版逐字节一致）；结构化数据 + 受控行内记号；
> DOMPurify 配置不放宽，注释内容用 React 渲染，不进 `dangerouslySetInnerHTML`。

## 1. 章节文件新增字段

章节顶层 dict 在既有 `{index,title,content}` 之上新增可选字段：

```json
{
  "index": 3,
  "title": "第一章 ……",
  "paragraphMode": "source",
  "content": [ {"type": "text", "value": "……正文{{n:1}}继续……"} ],
  "notes": [
    {
      "n": 1,
      "kind": "translator",
      "text": "参阅李维：《罗马史》1:8。",
      "imgs": []
    }
  ]
}
```

- `notes`：注释对象数组。`n` 为章内唯一逻辑注号（整数，迁移时保证唯一；显示号由阅读器重排，见 §3）。
- `kind`（可选）：`author`（作者注）/ `translator`（译注）/ `editor`（编注）/ `original`（原书注）。缺省 = 无署名区别，阅读器不加标签。
- `text`：注释正文纯文本。多段用 `\n` 分隔（阅读器按段渲染）；行内图与正文块同约定：`[IMG]` 占位 + 块级 `imgs` 数组按出现顺序。
- `notes` 存在时必须同时存在本章所有引用记号（§2）；二者一一对应由 `dp_note_check.py` 校验。

## 2. 行内引用记号（受控 token）

正文 text 块 value 中，注释引用点写作：

```
{{n:1}}
```

- 仅此一种格式：`{{n:` + 正整数 + `}}`，ASCII 字符，前后直接连接正文文字，不在 token 内部加空格或说明。
- 同一注释可被多次引用：`{{n:1}}` 出现多次，每次出现是一个独立"引用实例"，阅读器按出现顺序生成实例号 r1、r2……
- 记号只能由逐段实读后的迁移步骤放置（对应原书脚注/尾注标记的真实位置），**禁止正则盲扫正文生成**；
  数学区间 `[1,2]`、圣经章句「罗 1:17」、引文年份等一律不受影响——阅读器只识别 `{{n:x}}` 精确串。
- `html` 类型块不处理引用记号；迁移时若引用点落在 HTML 块内，必须把该块转为 text 或拆分后放置。
- token 两侧的正文文字必须保持原文完整；删除行内嵌注（OCR 页末脚注混入正文）时，只删注释正文本身，引用位与句子接续都要核对。

## 3. 显示编号规则（阅读器行为，全库一致）

- 显示号 = 按本章正文**首次引用顺序**重排：第 1 个被引用的注释显示 `[1]`，依此类推。
- 数据 `n` 仅是稳定标识，不等于显示号；迁移时应让 `n` 与首次引用顺序一致，阅读器重排只是兜底（分页 OCR 乱序、合并章重编号时不需要回改数据）。
- 无行内引用的注释（如原书章末集中注释中确实无标记者）：排在有引用注释之后，按数据序继续编号；迁移时应尽量找到引用位，找不到的登记待核，不得凭空造引用。

## 4. 阅读器行为契约（ChapterReader）

1. 正文 text 渲染时，`{{n:x}}` 渲染为右上角标按钮 `[显示号]`（sup，可点击、可 Tab 聚焦），不显示 `{{n:x}}` 内部记号。
2. 正文结束后渲染「注释」区：标题「注释」，每条 `[显示号]`（可点）+ kind 标签（作者注/译注/编注/原注）+ 注文（多段渲染、注内 `[IMG]` 渲染为行内图）+「返回」按钮。
3. 点击正文上标：滚动到对应注释条目并短暂高亮；同时把该引用实例记为该注的"最近入口"。
4. 点击注释编号或「返回」：滚动回**最近点击的那个引用实例**位置（重复引用同一注释时回到实际入口，不总是第一处）；无入口（URL 直达注释）时「返回」不显示。
5. 锚点 id 唯一：引用实例 `dp-ref-{章index}-{显示号}-{实例序}`，注释条目 `dp-note-{章index}-{显示号}`；同一时刻只渲染一章，无跨章冲突。
6. URL 深链：`/reader/{bid}?ch={章}&note={显示号}` 刷新后滚动到该注释；`ch/toc/sec` 既有行为不变。滚动均在阅读器滚动容器内完成，无固定栏遮挡。
7. 无 `notes` 字段或正文无 token：渲染路径与旧版完全一致，不注入任何额外 DOM。

## 5. 迁移与验收

- 迁移先做**逐条对应表**：旧标记（①/②/[1]/页末注等）、旧位置（文件+块号+偏移）、注文全文、kind、新 `n`、新引用点（块号+上下文摘录）。对应关系确认一条迁一条；跨页接续的注释要拼合完整后再迁。
- 不能删注释、不能把注文并入正文、不能编造对应关系；无法定位引用的注文保留在原位置（或原章末块），登记 `residuals` 待核，不算迁移完成。
- 每章迁移后运行 `backend/tools/dp_note_check.py {bid}`：`notes` 模式校验、`n` 唯一、token↔notes 配对、token 不在 html 块内、显示号重排确定性。
- 内容保全：迁移前记录块值原文，迁移后核对"正文（去 token）+ 注文集合"与原文的差量 = 被删除的行内嵌注集合，逐条列入台账（docs/tasks/book-full-proofread-zcode-2026-10-24/ledgers/）。
- 未经迁移的旧式注释（行内 ①、HTML sup 等）保持原样展示，行为不变；迁移只发生在逐书实读轮次内。

## 6. 版本

- v1（2026-10-24）：初始约定。字段只增不改；未来如需扩展（如注内链接），新增可选字段并保持旧数据可渲染。
