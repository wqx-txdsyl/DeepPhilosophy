# 章末注释数据约定 note-contract v1.7（2026-11-08）

> 适用范围：`backend/data/book_chapters/{bid}/{i}.json` 章节文件与前端阅读器（ChapterReader）。
> 目标：正文脚注引用 → 章末注释 → 原引用位置的双向跳转；全库统一格式，禁止每本书另发明格式。
> 原则：向后兼容，无新字段不启用新数学样式；已声明源段落的图文按原次序完整保留，修正原有漏图不受旧错误行为限制；结构化数据 + 受控行内记号；
> DOMPurify 配置不放宽，注释内容用 React 渲染，不进 `dangerouslySetInnerHTML`。

## 1. 章节文件新增字段

章节顶层 dict 在既有 `{index,title,content}` 之上新增可选字段：

```json
{
  "index": 3,
  "title": "第一章 ……",
  "paragraphMode": "source",
  "content": [ {"type": "text", "value": "……正文{{n:1}}继续……"} ],
  "notes": [
    {
      "n": 1,
      "kind": "translator",
      "text": "参阅李维：《罗马史》1:8。",
      "imgs": []
    }
  ]
}
```

- `notes`：注释对象数组。`n` 为章内唯一逻辑注号（整数，迁移时保证唯一；显示号由阅读器重排，见 §3）。
- `kind`（可选）：`author`（作者注）/ `translator`（译注）/ `editor`（编注）/ `original`（原书注）/ `recorder`（记录者，见下）。缺省 = 无署名区别，阅读器不加标签。
- `recorder`（v1.2）：语录体文献的记录者署名。只有原书姓名表与对应段末小字可直接支持时标注为此类，不以文字短小推测身份。正文对应入口和章末内容仍完整保留，读者可辨识其为署录而非解释性注释。
- `text`：注释正文纯文本。多段用 `\n` 分隔（阅读器按段渲染）；行内图与正文块同约定：`[IMG]` 占位 + 块级 `imgs` 数组按出现顺序。
- `inlineStyles`（v1.4，可选）：有原版逐处定位的数学 `sub`/`sup` 、引文黑体 `strong` 或斜体 `em` 范围，采用最终 `text` 的 UTF-16 `start/end` 半开区间；必须有序、不重叠、不切断字符，不能覆盖 `[IMG]` 或原注互引号。正文 text 块也支持此字段，但必须为 `paragraphMode: "source"`。只恢复原版格式，不凭数字外观推测上下标，不用相近 Unicode 字替换原字母。
- `editorialAddendum`（v1.2，可选）：整理者新增的校记纯文本，附于原注之后，另起一行并明确标「校：」。不能混入原注 `text`，不能包含正文引用 token，也不计作原文字词保全的证据。原注中补字的依据可在这里说明，原注本身的角色不因此改成编注。
- 注内每一幅图必须有且只有一个 `[IMG]` 对应位置。`imgs[].role: "formula"` 可用于经原图确认的分式等公式，以足够高度显示；`alt` 可提供经核对的公式转写。普通字形小图维持原高度，不根据尺寸猜测公式身份。
- 透明黑字原图可附 `background: "white"`，保证不同阅读底色下可读；仅接受固定白底，不接受任意样式。原文件按实际 MIME 类型保存，保持原始图片字节。
- `crossRefs`（v1.1，可选）：原注明确互引的对应表，如 `text: "见注[36]。"` 配 `crossRefs: [{"n":38,"start":2,"end":6}]`。`n` 指本章实际逻辑注号；`start/end` 为原 `text` 的 UTF-16 字符串偏移，取半开区间，必须完整覆盖原印 `[36]`。正文原字不改；阅读器在该位置显示目标注的当前显示号并可点击。不得以此字段为无正文引用的注释伪造正文入口。
- `crossRefs[].superscript`（v1.3，可选布尔值）：仅在原版确为注内上标脚注（如 `*` / `**`）且逐条确认调用位与注释定义时使用 `true`；原版星号统一显示为目标注的 `[x]` 上标。保留完整定义、原版对应表与所有非标记文字；普通“见注[x]”保持正文基线样式。
- 原注“同上”互引（v1.5）：仅在逐条核对原页、明确所指为本章某条已有原注时，可用相同 `crossRefs` 字段覆盖原文 `同上` 或 `同上。`。阅读器保留这几个原字，点击跳到明确目标，目标的返回按钮回到刚点击的“同上”。不得把原字换成新造的数字，也不得对全书“同上”批量猜配上一注。此类原文不允许 `superscript: true`；目标存在、UTF-16 范围、重叠和真实正文可达性检查均保留，任意其他词组不因本扩展成为合法标签。
- 真正的注中注无需伪造正文 token：校验器从实际正文 token 出发，沿合法的 `crossRefs` 检查可达性。无正文根的自环/循环、越界/重叠/缺目标/错误标签均不能使孤立注释免于待核。来源对应表仍是迁移的必要条件。
- `notes` 存在时必须同时存在本章所有引用记号（§2）；二者一一对应由 `dp_note_check.py` 校验。

## 2. 行内引用记号（受控 token）

正文 text 块 value 中，注释引用点写作：

```
{{n:1}}
```

- 仅此一种格式：`{{n:` + 正整数 + `}}`，ASCII 字符，前后直接连接正文文字，不在 token 内部加空格或说明。
- 同一注释可被多次引用：`{{n:1}}` 出现多次，每次出现是一个独立"引用实例"，阅读器按出现顺序生成实例号 r1、r2……
- 记号只能由逐段实读后的迁移步骤放置（对应原书脚注/尾注标记的真实位置），**禁止正则盲扫正文生成**；
  数学区间 `[1,2]`、圣经章句「罗 1:17」、引文年份等一律不受影响——阅读器只识别 `{{n:x}}` 精确串。
- `html` 类型块不处理引用记号；迁移时若引用点落在 HTML 块内，必须把该块转为 text 或拆分后放置。
- token 两侧的正文文字必须保持原文完整；删除行内嵌注（OCR 页末脚注混入正文）时，只删注释正文本身，引用位与句子接续都要核对。

## 3. 显示编号规则（阅读器行为，全库一致）

- 显示号 = 按本章正文**首次引用顺序**重排：第 1 个被引用的注释显示 `[1]`，依此类推。
- 数据 `n` 仅是稳定标识，不等于显示号；迁移时应让 `n` 与首次引用顺序一致，阅读器重排只是兜底（分页 OCR 乱序、合并章重编号时不需要回改数据）。
- 无行内引用的注释（如原书章末集中注释中确实无标记者）：排在有引用注释之后，按数据序继续编号；迁移时应尽量找到引用位，找不到的登记待核，不得凭空造引用。

## 4. 阅读器行为契约（ChapterReader）

1. 正文 text 渲染时，`{{n:x}}` 渲染为右上角标按钮 `[显示号]`（sup，可点击、可 Tab 聚焦），不显示 `{{n:x}}` 内部记号。
2. 正文结束后渲染「注释」区：标题「注释」，每条 `[显示号]`（可点）+ kind 标签（作者注/译注/编注/原注）+ 注文（多段渲染、注内 `[IMG]` 渲染为行内图）+「返回」按钮。
3. 点击正文上标：滚动到对应注释条目并短暂高亮；同时把该引用实例记为该注的"最近入口"。
4. 点击注释编号或「返回」：滚动回**最近点击的那个引用实例**位置（重复引用同一注释时回到实际入口，不总是第一处）；通过 URL 直达或直接翻到章末时，返回该注释的首次正文引用。无可定位的正文引用且未从另一条注释跳入时，「返回」不显示。
5. 锚点 id 唯一：引用实例 `dp-ref-{章index}-{显示号}-{实例序}`，注释条目 `dp-note-{章index}-{显示号}`；同一时刻只渲染一章，无跨章冲突。
6. URL 深链：`/reader/{bid}?ch={章}&note={显示号}` 刷新后滚动到该注释；`ch/toc/sec` 既有行为不变。滚动均在阅读器滚动容器内完成，无固定栏遮挡。
7. 无 `notes` 字段或正文无 token：渲染路径与旧版完全一致，不注入任何额外 DOM。
8. 注内 `crossRefs` 仅处理已核定的原注号或“同上”原字；数字标签显示目标注的当前号，“同上”保留原字。点击跳到目标注，目标注的「返回」回到刚点击的注内入口。编号重排不改变逻辑目标。注内图按整条注文的出现顺序取图，不能在每段重新从第一张图开始。

## 5. 迁移与验收

- 迁移先做**逐条对应表**：旧标记（①/②/[1]/页末注等）、旧位置（文件+块号+偏移）、注文全文、kind、新 `n`、新引用点（块号+上下文摘录）。对应关系确认一条迁一条；跨页接续的注释要拼合完整后再迁。
- 不能删注释、不能把注文并入正文、不能编造对应关系；无法定位引用的注文保留在原位置（或原章末块），登记 `residuals` 待核，不算迁移完成。
- 每章迁移后运行 `backend/tools/dp_note_check.py {bid}`：`notes` 模式校验、`n` 唯一、token↔notes 配对、token 不在 html 块内、显示号重排确定性。
- 内容保全：迁移前记录块值原文，迁移后核对"正文（去 token）+ 注文集合"与原文的差量 = 被删除的行内嵌注集合，逐条列入台账（docs/tasks/book-full-proofread-zcode-2026-10-24/ledgers/）。
- 未经迁移的旧式注释（行内 ①、HTML sup 等）保持原样展示，行为不变；迁移只发生在逐书实读轮次内。

## 6. 版本

- v1（2026-10-24）：初始约定。字段只增不改；未来如需扩展（如注内链接），新增可选字段并保持旧数据可渲染。
- v1.1（2026-11-06）：新增可选 `crossRefs`，保留纯文本原注与逻辑目标；校验目标存在、UTF-16 范围及完整原号，拒绝重叠或越界。旧数据无需转换。
- v1.2（2026-11-06）：可区分语录记录者署名及原注后的编校附记；两者均兼容已有章末注的双向入口，未设置新字段的数据保持原样。

- v1.3（2026-11-06）：区分原版注中注的上标调用，沿有效注内链接检查正文可达性；保留无真实入口的警告，不靠新增虚构正文引用消除警告。
- v1.4（2026-11-06）：按真实源位置恢复正文和注释的数学上下标；校验 UTF-16 范围、类型、重叠及原子占位边界。透明原图可显式使用白底。源段落中相邻或仅隔空格的图片全部按原顺序保留。
- v1.5（2026-11-07）：逐条有原页依据的“同上”可沿已有受控互引跳转并返回，保留原文；不自动识别或猜配，原有非法标签、无根循环及孤注检查不放宽。
- v1.6（2026-11-08）：经原版定位的黑体引文可使用 `strong`。范围仍按 UTF-16 验证，必须分开标注注号两侧的文字。
