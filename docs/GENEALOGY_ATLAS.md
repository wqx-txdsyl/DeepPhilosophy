# 哲学谱系页面

入口：`/genealogy`。流派详情仍使用 `/school/{name}`，现有图片和详情文件路径均保留。

- 时间：完整目录按原有年代字段排序，使用一条连续河道。
- 关联：地区用于稳定分组，连线根据已有详情中的共同核心哲人、共同问题计算。实线与虚线分别表示这两种关联，均不表示直接师承。
- 问题：28 个问题，支持与地区、流派名、哲人名和关键词交叉筛选。
- 当前视图、问题、地区、搜索和选择保存在 URL 中，进入详情后返回仍保留。

`app/public/gene/atlas.json` 是谱系目录的静态索引，图片与详情继续使用既有 public 资源。目录请求先读 OSS，失败时回退同源。完整详情仍以 `app/public/schools/data/` 为准。

修改流派详情中的哲人信息后，运行：

```sh
python scripts/sync_genealogy_catalog.py
node --test app/tests/genealogyAtlas.test.mjs
```

新增流派时还需在索引中补齐年代、地区、图片及详情映射，在 `genealogyTopics.js` 中配置问题归属。测试会检查目录完整性、所有图片和详情路径、哲人索引同步、问题覆盖、连续时间排序及多种宽度下的布局边界与碰撞。

发布检查（2026-10-02）：

- 谱系测试 8 项通过；新增的目录一致性测试 5 项通过。
- 元数据一致性校验：409 本书、409 个详情、332 本章节 meta 全部一致。
- 改动文件 ESLint 与生产构建通过；电脑和手机验证三种视图、搜索、问题选择、预览、详情跳转与返回。
- 全量后端测试初次检查：226 项通过、15 项失败、1 项跳过。失败涉及未跟踪的 AIAuthor 语料/向量索引，以及既有智能体流式容错测试的 LLM 环境。这些智能体代码未在本次修改。

发布先在 Cloudflare Pages 预览构建准备资源，抓取全部入口、懒加载 chunk 并同步 OSS，再发布相同提交到 master。生产检查需同时核对 Pages 提交、OSS 资源与页面交互。

旧 CI 未下载 Git LFS 目录文件，校验器现在会还原指针并核验 SHA-256 后比较元数据；无需改动工作流或扩大发布凭证权限。
