## 4. 检查内容

### A. 文字编码与残留噪声

检查替换字符 `U+FFFD`、乱码串、错误解码、NUL/异常控制符、无意义零宽字符、未还原实体、非正文 HTML/脚本残留、广告/水印、反复页眉页脚和混入正文的孤立页码。

混用中文、拉丁文、希腊文、公式、特殊符号或繁体字不自动算乱码。合法阅读器标记和锚点须先核对解析逻辑：例如 `[IMG]` 与规范中的 section 锚点不能一律作为脏文本。

### B. 错字、OCR 与排版损伤

检查形近字、漏字多字、重字、数字/字母与汉字混淆、人名术语不一致、标点与引号括号异常、英文断词、行末连字符、跨页断句、双栏阅读顺序错乱、脚注插进句子、注号与正文粘连、汉字间异常空格。

不要单凭词频、错别字词典或语言模型直觉判错。古旧译法、方言、繁简/异体、译名差异、作者有意重复及专门术语都要保留辨别空间。

### C. 通顺与上下文连续性

按章节顺序实读正文块，结合前后段、跨章首尾判断句法是否破碎、段落是否错序、两句是否误拼、逻辑跳跃是否源于缺文、是否有重复段落或章节、是否中途截断、是否缺正文而只有标题、章题与正文是否错配。

哲学原文复杂、译文生硬或观点不合常识，不等同于损坏。审计目标是文字与转录完整性，不把原著改成通俗讲解，不凭“更好读”重译，不擅自改动学术断言。跨章重复引文、书末索引、版权页、目录、注释、图表、公式或纯图片页须按角色判断，不机械要求每章正文达到同一长度。

### D. 结构与阅读落地

检查编号连续、顶层 `{index,title,content}`、内容块类型、空值、正文长度异常、meta/detail/catalog 章数与标题对应、toc 可点条目定位、section 块锚点以及图片标记在必要时是否影响阅读。对确证影响阅读的结构错误做最小修复，保留合法旧式内容，不无差别批量“升级”。

现行标准允许多种 section 实现，前后置内容可独立成章；不要为统一格式制造误报。源文件完整但线上打不开，应单列“交付/读取问题”，不要冒充文字错字；本地无镜像也不能直接认定线上缺文。

### E. 版本与出处

核对正文语言与书名/作者/译者/版本声明是否明显错配。PDF/EPUB 是来源格式，阅读质量必须以站内章节为准。不要把一本书另一译本的不同措辞当作错字，不把英文书擅自翻成中文补齐。

如需证实疑似错字、断裂或缺文，优先对照实际可用的同译者、同版次原文件或扫描页；记录来源路径/URL、版本、页码或章节/段落和本次实际可读范围。只能找到异译本、搜索摘要或无法访问时，明确证据不足，不得声称完成逐字对校。

## 6. 台账与问题记录格式

在任务目录创建以下输出，输出之间以 bookId、chapterIndex、issueId 关联：

- `book-audit.jsonl`：每本一条，含总章数、机器筛查章数、上下文读全章数、部分审读章数、原件对照章数、各严重度问题数、结论及未完成原因。
- `chapter-audit.jsonl`：每章一条，含文件 SHA、块总数、实际读过的闭区间 `reviewedBlockRanges`、未读区间、机器筛查结果、上下文审读状态、原件对照范围、issueIds、审读时间。
- `findings.jsonl`：每个独立问题一条，字段见下。
- `false-positives.jsonl`：已复核排除的代表性自动命中，保留规则、上下文理由；不要把所有中文生僻字标为错字。
- `repairs.jsonl`：逐项修复账，关联 issueId，记录原文、改文、理由/证据、改前/改后 SHA、复核结果、正式提交、发布与线上验证回执。
- `publication-batches.jsonl`：每批精确文件清单、关联问题、检查结果、提交 SHA、实际部署标识、OSS 增量清单与两端验收结果，失败项不得标成已发布。
- `summary.md`：用户可读的覆盖、重点问题、逐书结论、限制与下一批修复建议。
- 持续更新 `progress.json`：owner、当前 bookId/章/最后已读块、各项真实覆盖数、阻断与 nextAction，保留正确的输入版本。

`findings.jsonl` 必填字段：

```json
{
  "issueId": "唯一且稳定的编号",
  "bookId": "来自快照的id",
  "bookTitle": "目录正式书名",
  "chapterIndex": 0,
  "chapterTitle": "实际章题",
  "path": "backend/data/book_chapters/{bid}/0.json",
  "sha256": "发现问题时的文件摘要",
  "blockIndex": 0,
  "charStart": 0,
  "charEndExclusive": 1,
  "excerpt": "能精确命中的短原文",
  "contextBefore": "必要的短上文",
  "contextAfter": "必要的短下文",
  "category": "encoding|typo-ocr|punctuation|line-order|footnote|duplication|missing-text|structure|edition|delivery|other",
  "severity": "S0|S1|S2|S3",
  "status": "suspected|confirmed|source-original|false-positive|unresolved",
  "confidence": "high|medium|low",
  "reason": "具体损伤及上下文依据",
  "sourceComparison": {
    "status": "not-compared|compared|unavailable",
    "reference": null,
    "edition": null,
    "locator": null,
    "accessedAt": null,
    "readScope": null
  },
  "proposedCorrection": null,
  "correctionVerified": false,
  "relatedIssueIds": []
}
```

所有定位采用 **0 起**。字符位置按 Python Unicode code point、左闭右开；常见文字块针对 `content[blockIndex].value`。重复/跨章/文件不存在等不适用字符定位的问题，用 `locations` 数组及 `expectedPath` 等补足，允许上述不适用字段为 null，但须说明理由，不能编造 excerpt 或摘要。索引必须指向实际原文，不能引用清洗后文本的位置。

严重度：

- **S0**：整章/整书不可读、大面积乱码或错序、明显错书、读取失败等阻断。
- **S1**：改变句意的错字、疑似缺段/截断、大段误拼/重叠、关键脚注混入正文等。
- **S2**：局部错字/标点/空格/断行等一般阅读瑕疵。
- **S3**：尚不能定性的旧译法、疑似原版印误、术语/版本歧义及其他待查项。

severity 表示影响，不代替确证状态。未对照原件也可能确认技术乱码，但不能据此编造原文补字；书面“通顺”结论应说明是上下文审读还是原件对校。本任务明确授权有据修复；确认状态与修复/发布状态分别记录，不得把“发现”当作“已修复”，或把“推送成功”当作“线上已验收”。

同一问题在多个报告出现只计一次；同一页眉污染全书可建一个根问题附全部 occurrence 位置，另报影响章数。跨章缺口、重复章节关联记录，避免重复累计。自动候选数量与确认问题数量分别统计，书籍数、章节数、问题数不得混加。

- 普通局部错字/标点错误以同版原件直证优先；无原件时，仅处理上下文确能唯一确定且没有学术/译法歧义的明显技术损伤，明确依据类型，不能声称经过原件对校。
- 缺文、乱码替换字、人名、否定词、术语、数字、公式、引文及可能改变意思的错误，取得可靠对应原文后修复。无法确定的内容保持原状并列未解决项，不用 AI 续写补缺，不用别的译本偷换。
- 局部重抽/OCR 先对照原件和相邻段落，核对没有丢字、重段、错序。移除页眉/页脚/噪声要保留依据，禁止全库大正则未经复核直接写回。
- 不覆盖尚未提交的他人数据；发现并发写入时保留检查点和准确差异，确认 owner 后再写。禁止 reset/clean/强推和篡改质量基线。

### 9.2 必要验证与同步

1. 每批限定明确的书、章、问题与路径；对修改块及邻接上下文实读复核。确认内容块顺序、引号/脚注、图片标记、跨章衔接和 TOC 锚点不被破坏；删除/合并块尤其要核对 section 的 sec 定位。
2. 按现行单书同步入口 `backend/tools/dp_sync_books.py --only <bid>` 同步该书目录/详情/开发镜像，先查看当前 CLI 和实现。禁止无差别全库写回。检查同书 chapterCount、chapterTitles、toc、编号文件，以及源/开发镜像摘要一致；同步不得覆盖人工元数据或其他书条目。
3. 对本批书运行 `backend/tools/verify_book.py <bid> --vite-check`，必要时启动本地预览并按当前 CLI 指定地址；检查真实修复章和锚点。自动检查仅跑适用范围，失败须明确原因并处理，不能把旧失败当成通过。
4. 若 books.json 改动触发书目参考输入摘要变化，按已有 `backend/tools/dp_biblio_build.py` 流程更新必需生成件并跑对应一致性回归。核对 `backend/data/book_bibliography.json`、`docs/evidence/PHIAGENT_O7B_BIBLIOGRAPHIC_PILOT_MANIFEST.json` 是否确有必要；不手改摘要骗过检查器。纯正文修复未影响这些输入时不制造无关生成变更。
5. 每批提交前检查 diff、JSON/JSONL、正式路径与影响范围；源数据与台账都要保留，精确 pathspec 暂存，用 `git commit -F`，不得 `git add -A`。提交消息符合项目 type: 描述规范。
