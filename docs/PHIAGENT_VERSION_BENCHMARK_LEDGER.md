## 百分制如何计算

汇总协议版本：**aggregation 1.0.0**。这层汇总是本次按用户要求新增的报告约定，不回写或冒充原冻结规范已有的百分制规则。

1. **逐项评分不变。** C 的权重依次为 10、15、20、10、5，共 60；研究任务还含 R 的 15、15、10，共 40；每项仍取 0–4 或 U。K 核验四项仍取 0/1/U。
2. **只在汇总计算中统一比例。** C 回合贡献为 `C精确分 / 60 × 100`；R 为 `(C精确分 + R精确分) / 100 × 100`；K 为 `K正确项数 / 4 × 100`。不把原始单题成绩改写为新量表。
3. **先回合、后题目。** 一题的全部规定回合等权平均；再对 70 题等权平均。每题权重 1/70，J 组 3–4 轮不能比单轮题多占权重。14 组各 5 题，完整集上也等价于组内平均再对 14 组等权平均。
4. **用未取整分计算，最后显示取整。** 不拿历史表格中的整数分再求均值，也不按回答字数、工具次数或耗时加权。
5. **未知与未测不是零分。** U 的维度贡献保持未知；未测题保持未知。将未知项在其合法最小值与最大值之间变化，得到数学可取范围。它不是统计置信区间，也不覆盖评分器自身的偏差。缺口补齐前，完整集总分为“未完成”，不取区间中点。
6. **缺陷不能被均分洗掉。** 冻结规范的 confirmed/pending 严重错误及原始判定完整保留。规范没有规定“一项严重错误把数值归零”，因此不凭空新增扣分公式；高均分不意味着通过验收。

统一公式：`S = (1/N) × Σ题目[(1/T题目) × Σ回合(100 × 已得分 / 该任务满分)]`。完整集 `N=70`；局部结果必须随分数注明 N 和题号范围。未来完整 70 题都可确定计分时，此处才输出单一的全套百分制分数。

本表四个范围固定解释如下：

## v0.1.0 极简基线

代码参考：`575955a1ef7b35aae1d611b44ba712ac27e77a21`。实测批次：2026-09-29 的 run1。提示词原文共 **23 字符**：

> 你是深哲（PhiAgent），一个哲学智能体。

原文归档：[general-0.1.0.md](../backend/prompts/general-0.1.0.md)，SHA-256：`8c366cfb11a639f541f0669c48fc761cbe2be6f31fe33bd0f2130a662f509429`。

### 实际架构与执行逻辑

生产接口 `/api/agent/stream_lg` 委托 `engine_langgraph.stream_agent`；当 `agent=general` 且 `DEEP_AGENT_RUNTIME=bare`（默认）时，入口立即转入 `deep_bare_agent.stream_bare_agent`。因此虽然入口文件叫 LangGraph，**此次通用深哲执行的是 bare 的消息循环**，不走旧 controlled 图中的研究声明、预算、校验修复闭环。

循环为：身份 SystemMessage + 已传入用户/助手历史 + 当前问题 → DeepSeek 带工具的流式调用 → 若要求工具则执行 → 将真实 ToolMessage 返回模型 → 下一轮；模型停止请求工具时输出最终答案和显示用引用。一个回合内的工具并发执行，回传消息保持原请求顺序；错误作为工具结果交回模型。中间公开文本、供应商 reasoning、工具事件分别流出；引用整理只生成展示元数据，不重写或拒绝答案。

主模型为实测记录中的 `deepseek-flash`；代码默认 temperature 0.7、thinking enabled、reasoning_effort high。历史记录未保存完整生效配置指纹，环境覆盖不能逐项追溯。

### 哪些约束没有，哪些依然有

|层级|v0.1.0 的实际行为|
|---|---|
|主 agent 调度|没有工具调用次数/循环轮数预算；不因重复调用而拦截；不做框架级上下文截断|
|主模型客户端|bare 重建客户端为 `max_tokens=None`、`max_retries=0`、`timeout=None`；不是无限供应商上下文或无限输出能力|
|质量与研究策略|无自动答案审校/改写、无强制研究声明、无必须查几次、无主循环语义收束门禁|
|工具接口|仍有 JSON schema、参数合法性、结果数量、来源及网络安全边界；工具错误不会被伪装为成功|
|工具内部|`search_books` 返回 1–10 项、章节窗口默认 2800 字符；联网有单次超时、重定向与下载体积边界。这些是单工具契约，不是主 agent 总预算|
|生成型工具|仍有内部提示词及各自输出限制。如 advisor_council 固定亚里士多德、斯多葛、存在主义框架，仍可能塑造主回答|
|外部条件|供应商容量、余额、网络权限仍然限制执行；评测每轮 600 秒超时只属于采集实验|

所以“极简提示词”仅指**主系统提示极简**，不意味着整个系统只有一句指令、没有工具提示或底层边界。工具注册表及配置的 MCP 工具仍然交给模型自主选择；没有证据证明历史运行实际安装了多少个外部 MCP 工具，不补造固定总数。

## v0.1.1 首次提示词修订

代码参考：`ea2c286bf70083c01972e5fe127761da94d298e6`。实测批次：2026-10-02 的 run2。主提示词 **642 字符**，完整原文：[general-0.1.1.md](../backend/prompts/general-0.1.1.md)，SHA-256：`33e9bacbeb5fbec8a977c1b339c421dcbcb575a8a9aea45626013a257667fba6`。

新增判断原则：

- 从真实困惑推进哲学分析；操作、核验与短答按用户范围完成，不固定套流派。
- 保持主体、条件和比较范围；区分必要/充分、事实/价值、有效/为真；结尾不超过理由。
- 涉及现行政策、职业规范和最新研究时主动核查；原典和研究服务于论证。
- 区分书目、摘要、片段、全文；未命中和工具失败不能推出不存在。
- 生成型工具仅提供候选意见，主模型要独立检查其假设及推论。

**没有在这次修订中增加工具预算、改主模型、改工具内部提示或接入自动审校。** 两个历史提交间后端差异只有 `engine_langgraph.py` 的主 SP 和 `deep_bare_agent.py` 的模块说明，核心 bare 循环相同。

但 run2 的环境另外变化了：从备份恢复 scholarly_cache；在本机受信 TUN 代理条件下显式使用 `SCHOLARLY_NETWORK_MODE=TRUSTED_PROXY`。当时尚未修复缓存 null 的代码根因。run2 有 48 项未提交记录计数，却没有完整路径/源码 hash，不能把记录的 Git commit 当成完整运行环境快照。

结果：65 完成、5 跳过、77 轮、1218 次工具、墙钟 46分01秒。学术工具 157 次返回中 123 success、24 partial、10 error；75 次学术读取中 74 次有摘要、1 次仅元数据，**没有论文全文证据返回**。网页读取 137/198 成功。

百分制见总览；原始评分：[v0.1.1 SCORES](evidence/phiagent_benchmark_v0_1/quality_review_run2_v1_2_20261002/SCORES.json)。[维度理由](evidence/phiagent_benchmark_v0_1/quality_review_run2_v1_2_20261002/SCORES_AND_REASONS.md)与[执行对照](evidence/phiagent_benchmark_v0_1/LIVE_RUN2_EXECUTION_AUDIT.md)可追溯。SP、环境、日期及在线来源同时变化，因此成绩差异不是提示词的单独效果。

## v0.1.2 后端与提示词候选修订

实现参考：`bc05d0527`、`884fd6130`，本次统一命名后使用产品版本 **0.1.2**。历史的 `2.0.0-rc.2` 和误填的 `0.2.0` 是这一候选阶段的旧发行编号，原 Git 标签保留；新的版本名称不改变既有测试记录。

### 后端改动

- 学术缓存根值与字段形状检查、异常内容留档、锁与原子写入，修复 null 导致整条通道异常。
- 摘要支持 `offset/max_chars` 续读，返回实际范围与 hash；明确区分元数据、已取得摘要、正文节选。`available_abstract` 不声称上游摘要完整。
- 章节/引文工具返回真实 `https://deepphilosophy.top/reader/{book_id}?ch={chapter_idx}`；仅承诺章节级定位，不把字符位置冒充阅读器锚点。
- 按书籍、章节与同版正文 hash 记录连续阅读区间，避免不同版本拼成“读完”；正文抽取不能证明原版排印。
- 新采集器保存事件时间、call ID、分段信息、有效 prompt、模型/依赖/代码指纹；每题隔离记忆，严格在 DONE 后结束，支持同配置续跑；记录主模型 usage，辅助模型成本另计。
- 前端版本、后端健康/版本接口、SSE 发行信息和 manifest 使用统一产品版本。

bare 主循环仍不加工具预算，不增设答案正则改写或强制研究次数。论文全文可达性、秘塔未接入、OpenAlex 限流、生成型工具内置模板没有因此全部解决。

### 同期并入的账号与前端改动

从 v0.1.1 参考提交到当前代码，还合入了工具结果可读化、原典引用格式兼容、底部操作统一、针对性探索问题、账号历史/长期记忆、个性化首页、移动端布局/复制和重登录恢复。这些不能遗漏在完整产品版本沿革之外，也没有被旧 run2 的进程内评分覆盖。

新 bare 引擎加入账号记忆工具；登录时将 explicit_memories 与 recent_questions 作为标注为数据的账号背景消息送入模型，随后仍接历史与当前问题。它不是隐形地改主 SP，也不是保证自动形成可靠的长期知识。新版在 DONE 后可另行生成探索问题；正式基准采集器在 DONE 即关闭，因此答题耗时和主模型 usage 不包含这段后处理。

### Prompt 改动与当前启用状态

候选原文 **879 字符**：[general-0.1.2.md](../backend/prompts/general-0.1.2.md)，SHA-256：`8b3f62535fad2755afb2d7a519805eb0dad7af2fb469b0eb981cd3a8e96c041e`。

相对 v0.1.1，进一步强调：提问不等于断言；不替用户补造心理成因；在原假设内分析；事实/类型不同不自动证明价值更高；责任、理解与贡献不能混成资格；制度定义和例外必须核查；类比应说明限度；结论不能偷偷扩大范围。

**发行代码版本与启用的 prompt 分开记录。** 2026-10-03 按用户要求，manifest 默认提示词从 0.1.1 切换为 0.1.2，代码与默认 SP 均为 0.1.2。此前代码虽已标记 0.1.2，默认仍使用 0.1.1 兼容 prompt。此次启用采用上列既有 879 字符模板，不改其内容；截至启用时尚无全套质量评分；后续 RUN3 为开发暂定评审，不能据上线推定质量提升。

当前框架会给选定模板追加语言指令；对中文是“使用中文回答和思考；引用外文时区分原文与译文，不把自译当作来源原文。”因此在新框架里选历史 profile 只复用了旧模板，并不完整重现当年引擎与所有生效消息。回放历史须连同旧代码和环境判断。

### 局部试跑与 RUN3 的区别

用户决定暂不进入工具调优，追加v0.1.4，仅改主提示词及必要版本登记。v0.2.0暂缓，不默认在本轮后自动开始；仍由用户运行下一轮测试集。

本轮复查到一处具体约束丢失：v0.1.1明确说明“生成型工具提供的是候选意见，不是权威证据或必须沿用的回答框架”，v0.1.2/0.1.3没有保留该条。RUN4 A01的流派框架与A04的心理归因、厨师口味类比，可以在advisor_council/life_coach回执里找到对应内容。这是可核的传播线索，不足以单独证明全部退步由此造成。v0.1.4恢复并前置该条，不修改或移除工具。

|修订位置|针对问题|本轮做法|
|---|---|---|
|任务边界|I01禁止查询仍查资料|明确只据假设/不查资料时不调用检索与读取工具；工具自主性服从任务|
|用户处境|A04把一般道理说成个人心理原因|开放提问不当既定立场；可能解释不升格为诊断；不替用户补写动机|
|工具意见|A01/A04复用生成型工具预制框架|候选意见单独核对其假设与推论，不作为原典、用户事实或必用结构|
|多轮条件|G01/J01/J02扩大或丢失假设|保留主体、量词、效果与动机；后轮仅改变明确更改的条件|
|结论检查|B04必要条件变充分，J02无普遍证明变无理由|责任/贡献/资格分查；强量词检查同条件反例；总结保留全部必要条件|
|材料状态|D04臆测版面、F02误认长度、E05误认目标未读完|区分坐标、总长度与实际窗口、目标段与整章；禁止用未见排印作确定事实|

主提示词：[general-0.1.4.md](../backend/prompts/general-0.1.4.md)。不写入题号、固定答案、禁用工具名单、次数或token预算，不增设分类器、正则、答案改写或自动重试。工具契约保持0.1.2，运行源码与数据库不变。仅检查配置指纹、版本一致性、旧分数不变及线上启用状态；不调用模型答题或评测，v0.1.4评分留空。
