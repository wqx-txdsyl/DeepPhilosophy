# 迁移方案（migration-plan）

日期：2026-10-04。本方案供 Codex 在审校结论基础上统一应用时使用。**本阶段只交计划，未改动任何正式数据**；所有正式源（`app/public/schools/data/`、`app/public/gene/atlas.json`、`schools/catalog.json` 派生索引）在应用前保持现状。

## 0. 应用前必须先解决的一件事：版本分叉

审校基线是提交 `657399382116e24aa45336c1302dc5c21dd53652`。多个批次独立发现**当前工作区的部分页面与该基线不一致**（详见各批次 reason，典型：前苏格拉底哲学、伊壁鸠鲁学派、怀疑论、新柏拉图主义、犬儒学派、分析哲学等页的工作区版本回退或分叉，而古埃及页的工作区版本反而含部分修复）。应用任何改动前必须：

1. `git diff 65739938 -- app/public/schools/data/` 逐文件清点分叉；
2. 逐页裁决"以基线为准"还是"以工作区为准"（审校结论对**基线文本**负责；若裁决采工作区版，需把受影响子项按本台账结论重新映射，不能直接套用）；
3. 裁决记录回写进台账各条 `reason` 后再动手。

## 1. 字段级改动清单（每条子项）

对每条 `reviewStatus=reviewed` 的出现记录，按 `review-ledger.json` 应用：

| 台账字段 | 落到正式源的字段 | 说明 |
|---|---|---|
| `recommendedActions=改名` | `subSchools[i].name` | 必须同步写 `alias`（或等义字段）保留原名，见 §3 |
| `recommendedActions=改类型` | `subSchools[i].kind`（若无此字段则新增） | 值用台账 `entityKind` 的规范短词（学派/传承/个人体系/立场/方法/时期/接受史/主题/教义方面/文本/领域/编辑概括） |
| `chronologyAssessment` 修正 | `subSchools[i].era` | 保留"约年/范围/不详"口径，不伪造精确年代 |
| `relationAssessment` | 展示分组与 `kind` 联动 | "共同问题或编辑比较""后世接受"的条目**不再以子流派版式展示**，但内容保留 |
| `proposedCanonicalEntityId` | 实体层（见 §4） | 多父项实体共用一份资料 |
| `desc` 微调建议 | `subSchools[i].desc` | 仅台账 reason 中点名的事实性错误（年代、人物归属）才改；不整段重写 |

**不改**：`proposedRelations` 仅为关联建议，应用时转为页面 relations/交叉引用，不得覆盖现有 relations 里正确的条目（多页 relations 现有串写错误见 §5，先修复再增量）。

## 2. 父项级改动

- **类型标注**：111 项 `proposedParentKind` 落到页面 meta（`kind` 字段），供聚合与计数使用（见 §6）。
- **迁移（6 条）**：SUB-0076（前苏格拉底→阶段说明块）、SUB-0193（司各脱此性论→经院哲学页+唯名论页改对立比较）、SUB-0288（浪漫主义哲学→SCH-055）、SUB-0325（约纳斯→环境/技术哲学页）、SUB-0459（与父项重复→并入）等，全部在 `subschool-decisions.md` 表二。迁移=把内容块搬到目标父项并保留来源注记，**原位置留交叉引用，不删块**。
- **待裁决的父项边界（2 项，未裁不动作）**：SCH-033/SCH-034（伊斯兰哲学 vs 阿拉伯哲学：合并或窄化分工）、SCH-066（北美哲学：改名"美国哲学"或补加拿大）。裁决前其子项一律按台账登记的规范实体处理，避免双处维护。

## 3. 旧入口兼容（改名不造成 404）

现状：子项路由存在"通过名称取某个父项"的逻辑。因此：

1. 建**别名映射表**（建议 `app/public/schools/data/_aliases.json` 或并入派生索引）：`{旧名: {canonical: 新名, parentId: 父项ID}}`，覆盖全部 139 处改名 + 9 处疑似异译；
2. 名称查找逻辑改为"精确名 → 别名表 → 规范名"，**禁止靠调整父项数组顺序消歧**；
3. 12 组同名重复的多父项入口在别名表中各登记一条（同 canonical、不同 parentId）；
4. 本方案不提出任何 URL/路径/文件名变更，页面文件名、图片、缓存版本一律不动；
5. 应用前 `grep -r "旧名" app/src/` 确认没有组件硬编码旧子项名。

## 4. 规范实体层

`canonical-entities.json`（62 实体，25 个多父项、14 个有异名）作为实体层来源：

- 每实体一份共享资料（名称、异名、年代、概述），多父项出现以"关联"挂接，**不得复制成多份内容**（现状如息结派/希解派两份 desc 各写一半，合并后互补）；
- 实体 ID 直接采用台账 `ENT-*`，新增实体沿用同一命名法；
- 先落数据结构（`entities/` 目录或 detail 内嵌），再改渲染，分两个提交。

## 5. 独立于分类的数据勘误（建议先行，一个独立提交）

审校顺带发现的**页面级硬错误**，与分类结论无关，可先修：

- **relations 串写**：兵家/法家/名家/阴阳家页四页互相串挂（阴阳条在兵家页等）；道家↔儒家↔墨家模板错置（张载四句两页重复）；宋明理学页混入纯佛教 relations、closingQuote 为《华严经》语；隋唐佛学页 relations 是魏晋玄学人物、closingQuote 为王弼语；三民主义页 relations 误植康梁；习思想页 relations 与本体系无构成关系；两汉经学页 closingQuote 为孙武语；西马页混入解放神学引文。
- **人物/著作错配**：北极页 Magga（萨米）标成因纽特、Tagaq 反之、《Split Tooth》移名给查无此人者；玛雅页"约翰·洛克(1939-2016)"实为 Dennis Tedlock；黑人页"克里斯蒂安·沃尔夫(1952-2021)"实为 bell hooks（与 18 世纪德国哲学家同名冲突）、"约翰·洛克"应为阿兰·洛克；高加索页 works 系统错配；澳洲页 Kanyini/Alcheringa 归属可疑。
- **纪年错误**：法藏卒年 730→712；马丁-巴罗 1998→1989；古铁雷斯 1970/弗莱雷 1971 疑互换；格巴拉 1947→1944；唐君毅/牟宗三卒年互换；韩国页"圆晓"→元晓；中国科学社 1930→1914/15；马蒂、塞亚生年两处自相矛盾；芒福德"巨机器"年代偏早；《大札撒》"成文法典"表述软化。
- **疑似虚构条目**（应用前必须再核）：北极页"阿勒西奥·库马拉"、高加索页"阿布·穆斯林·阿特-图尔基"、原住民页"瓦利·萨利"、凯尔特页"凯瑟琳·帕克"、高加索-草原页"迪娜拉·杜达罗娃"。

## 6. 计数与统计口径

- 子项 `kind` 落地后，"学派数量"类统计（首页/谱系页）改为**按 kind 计数**：只有 kind∈{学派,思想运动} 才计入，主题/立场/时期等不再冒充学派数；
- `schools/catalog.json` 与 `atlas.json` 派生索引在正式源改动后重建，不手编；
- 旧名入口经 §3 别名表继续解析，前后端统计口径同步切换。

## 7. 与 zcode 内容补充的衔接（防覆盖）

- 分工不变：Codex 独占 `app/public/schools/data/` 与索引；zcode 独占 `docs/content-proposals/schools/<taskId>/`；
- `gap-delta.json` 已把 242 条缺口对接到 59 项任务（68 条复用/调整既有任务）或 168 个新提案（GAP-EXTRA-001~168）；**新增候选不自动立项**，由 Codex 对照 zcode 产出后决定；
- 应用顺序建议：先分类与勘误（本文档 §1/§2/§5）→ 再接 zcode 首批 12 项资料包 → 最后处理 GAP-EXTRA 候选，避免两边同时改同一父页；
- 若审校结论否定了某项既有补充建议（台账中 action=无需新增/证据不足共 30 条），在任务表中标注撤回原因，不静默删除任务 ID。

## 8. 应用后的验证

1. 每页改动后跑结构校验（subSchools 顶层 dict、kind 枚举、别名表覆盖全部改名）；
2. `grep` 全部旧名：正式源 0 直接出现（仅别名表含）；`app/src/` 0 硬编码旧名；
3. 统计口径切换后核对：详情页学派计数 = kind∈{学派,思想运动} 的子项数；
4. 前端 `npm run build` + 相关页面手测：改名子项路由可达、多父项实体两个入口都渲染、无 404；
5. CF Pages 构建产物与 OSS 双轨（涉及静态数据时两条管线都跑）。

## 9. 明确不做的事

- 不删除任何子项内容或公共路径；"称不上学派"一律降级/改名保留；
- 不运行 `add_school.py`/`add_subschool.py` 批量造派；
- 不在裁决前（§2 两项边界、§0 版本分叉）改动对应页面；
- 不把 GAP-EXTRA 提案直接写成正式条目。
